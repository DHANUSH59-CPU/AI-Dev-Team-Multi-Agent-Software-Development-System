Context Builder

Before coder runs, it resolves dependencies using 3-tier lookup:

  • Tier 1: Exact filename match in registry
  • Tier 2: Fuzzy / partial string match
  • Tier 3: Disk fallback — regex scan file contents
Zero LLM tokens — pure Python static analysis

Debugger Escalation

  • Tier 1: Fix with local error context
  • Tier 2: Fix with broader codebase context
  • Tier 2.5: Roll back to last good snapshot
  • Tier 3: Escalate to human — ask for guidance
Prevents infinite loops while staying resilient

Blueprint Validator (no LLM)

Runs 5 cross-checks after architect phase:

  • All API routes reference existing DB tables
  • All foreign keys reference valid tables
  • No orphan tables (every table used by an API)
  • Auth consistently applied on protected routes
  • Naming conventions are consistent

File Registry

Tracks every generated file with:

  • File path
  • Exported functions/classes
  • Import statement template
  • Interface/type definitions
O(1) lookup by filename (Python dict / hashmap)

❓ Technical Q&A — Project Specific

Read Q, cover A, try to answer, then check

Q1: What is LangGraph and why did you use it over plain Python functions?
LangGraph is a library for building stateful, graph-based AI workflows. With 27 nodes, managing state with plain functions becomes spaghetti. LangGraph enforces that all nodes communicate ONLY through a shared state object with defined reducers — making it predictable and debuggable. It also handles conditional routing, loops, and checkpointing natively.
Q2: How does the shared state work? What are reducers?
Every node reads from and writes to a single AgentState TypedDict. Reducers define how new values merge with existing ones:

• last-write: new value overwrites old (e.g., currentTask)
• merge_objects: shallow merge {**old, **new} (e.g., blueprint)
• accumulate: append to list (e.g., conversation history, file registry)

This means nodes are pure functions — given state in, produce state out. No side effects.
Q3: What is checkpointing and why is it critical here?
After every node, LangGraph serializes the full state and saves it to Redis. A full run takes 30–60 minutes with 100+ API calls. If it crashes at node 20, I resume from node 20 — not the start. Implemented with langgraph-checkpoint-redis, with fallback to in-memory if Redis is unavailable.
Q4: Explain the self-healing dev loop.
Core loop: select task → build context → generate code → review → execute in Docker → snapshot.
If execution fails: debugger escalates through 3 tiers (local fix → broader context → rollback → human).
If reviewer rejects 3 times: simplifyTask agent breaks it into smaller subtasks.
Every success saves a snapshot for rollback. This prevents infinite loops while staying resilient.
Q5: Why Docker for code execution? How do you use it in Python?
Generated code is untrusted — running on host could delete files, consume resources, or make unauthorized network calls. Docker provides OS-level isolation.
Python's docker SDK is used to: create containers, bind-mount the generated project folder to /app, execute commands via docker exec (e.g., running tests, npm install), and clean up containers when done.
Q6: How do you control LLM costs?
Three ways:
1. Hard token budget — default $2, configurable via env var, throws exception before calling API if exceeded
2. 15 of 27 nodes use zero LLM calls — routing, validation, and state management are pure Python
3. One file per LLM call — prevents token truncation so no tokens wasted on failed/partial outputs
Q7: What is the InputBridge pattern for human-in-the-loop?
When the system needs human input, it can't block the main process. The agent emits a WebSocket event to the dashboard and awaits an asyncio.Future(). When the user submits their answer via the UI, the WebSocket handler calls future.set_result(answer) which resolves the Future and the agent resumes. The event loop is never blocked.
Q8: How does the Blueprint Validator work? Why no LLM?
It's a pure Python function — no LLM. Runs 5 structural checks: all API routes reference existing tables, all foreign keys are valid, no orphan tables, auth consistently applied, naming conventions consistent.

Using code instead of LLM makes it 100% deterministic, instant, and costs zero tokens. LLMs can hallucinate — for validation you want guarantees.

🐍 Python Concepts Q&A

Q9: What is asyncio? Where did you use it?
asyncio is Python's built-in library for asynchronous concurrent code using an event loop with async/await. Used in:
• FastAPI backend handles multiple WebSocket connections concurrently
• InputBridge uses asyncio.Future() to pause an agent without blocking
• Gemini API calls are async so multiple agents can run without blocking each other
Q10: What are TypedDicts and why did you use them for AgentState?
TypedDicts are Python type hints for dictionaries with defined key-value types. Used for AgentState (30 fields) to: catch type errors at development time, enable IDE autocomplete, serve as documentation, and let LangGraph validate state shape at runtime. Zero runtime overhead — pure annotation.
Q11: What is a generator? How did you use one?
A generator uses yield instead of return. It produces values lazily — one at a time — instead of loading everything into memory. When streaming Gemini API responses, the SDK returns a generator of chunks. I iterate it with for chunk in response_stream without loading all chunks into RAM — critical for large code generation responses.
Q12: Difference between deepcopy and shallow copy? Where did you use each?
Shallow copy copies the outer object but nested objects share references. Deep copy recursively copies everything independently.

• Shallow merge used in merge_objects reducer: {**old_state, **new_updates}
• copy.deepcopy(state) used in snapshotManager to save rollback points — must be truly independent copies otherwise modifying active state corrupts the snapshot.
Q13: What OOP principles did you apply?
• Encapsulation — Each agent class encapsulates its prompt logic and LLM parsing
• Inheritance — BaseAgent has common logic (Gemini call, retry, token tracking); specific agents extend it
• Polymorphism — All agents implement a .run(state) method; LangGraph calls them uniformly
• Abstraction — SandboxManager hides Docker complexity behind create(), execute(), cleanup()
Q14: What is a decorator? Give an example.
A decorator is a function that wraps another function to add behavior. Example from the project:
@app.post('/api/projects') — FastAPI route decorator maps HTTP POST to an async function
@graph.node — LangGraph node registration
Under the hood, @decorator is syntactic sugar for func = decorator(func).
Q15: Process vs Thread vs Coroutine — which did you use and why?
• Process: separate memory, heavy, true parallelism
• Thread: shared memory, GIL limits CPU parallelism in Python
• Coroutine (asyncio): single thread, switches at await points — best for I/O-heavy tasks

Used coroutines because the workload is I/O-bound (waiting for Gemini API, Redis, Docker) not CPU-bound. asyncio handles 100+ concurrent I/O operations efficiently with one thread.

🧮 DSA Q&A

Q16: What data structures did you use in your project?
• Queue (FIFO) — Task queue: phases processed in order
• Stack — Snapshot history: snapshots.append(state) then rollback = snapshots.pop()
• Dict/HashMap — File registry: O(1) lookup by filename
• Graph (DAG) — LangGraph itself: 27 nodes + directed conditional edges
• List (append-only) — Event log, conversation history, token call records
Q17: What is the time complexity of file registry lookup?
• Exact match: O(1) average — Python dict is a hash table
• Fuzzy match: O(n·m) — linear scan, n=registry size, m=string length
• Disk fallback: O(f·c) — scan f files, c chars each

For a typical project (20–30 files) this is negligible. For large codebases, could optimize with a Trie for prefix matching or an inverted index.
Q18: Write Python code to detect a cycle in a task dependency graph.
def has_cycle(graph: dict[str, list[str]]) -> bool:
    WHITE, GRAY, BLACK = 0, 1, 2
    color = {node: WHITE for node in graph}

    def dfs(node):
        color[node] = GRAY
        for neighbor in graph.get(node, []):
            if color[neighbor] == GRAY:   # back edge = cycle
                return True
            if color[neighbor] == WHITE and dfs(neighbor):
                return True
        color[node] = BLACK
        return False

    return any(dfs(n) for n in graph if color[n] == WHITE)
DFS with 3-color marking. GRAY = currently in path. Finding a GRAY neighbor means back edge = cycle. Time: O(V+E)

Q20: What is indexing? Where would you add indexes in this project?
An index is a data structure (usually B-tree) that lets the DB find rows without a full table scan.

In the Todo app: index on todos.user_id (every query filters by user), index on todos.due_date (sorting/filtering by date is common). Without these, every query scans all rows — O(n) instead of O(log n).

🤖 AI / ML Q&A

Q21: What is a Large Language Model (LLM)?
An LLM is a deep learning model trained on massive text data using the Transformer architecture. Self-attention mechanisms allow it to weigh relationships between all tokens in the input simultaneously. Given a prompt, it predicts the most probable next tokens. I use Gemini 2.5 Flash which supports up to 65,536 output tokens and native JSON mode.
Q22: What is prompt engineering? Give an example from your project.
Crafting input text to guide LLM behavior reliably. Example — coder agent prompt structure:
1. Role: "You are an expert backend developer"
2. Constraint: "Generate ONLY the file: {task.filename}"
3. Context: "Follow these existing patterns: {patterns}" + "Available imports: {file_registry}"
4. Format: "Return ONLY valid JSON: {'filename': '...', 'content': '...'}"

Key techniques: role assignment, hard constraints, few-shot examples, strict output format.
Q23: What is a multi-agent system? Why not just one big LLM call?
A multi-agent system uses specialized agents for different subtasks. One big LLM call fails because:
• Context window limits (can't hold 25 files + all history)
• Errors compound — one mistake in a long chain corrupts everything downstream
• No specialization — a generalist prompt is worse than a focused prompt

My solution: PM specializes in requirements, Architect in system design, Coder in one file at a time — each with short, focused prompts that fit cleanly in context.
Q24: What is RAG? How does your project implement it?
RAG (Retrieval Augmented Generation) combines a retrieval system with an LLM — instead of relying only on training data, relevant documents are retrieved at query time and injected into the prompt.

My contextBuilder is a form of RAG: before the coder generates a file, it retrieves relevant existing files from the file registry and injects them into the prompt as context. This ensures the LLM generates accurate imports, uses real function names, and follows actual patterns from the codebase.
Q25: What is the difference between SQL and NoSQL? When does your architect recommend each?
• SQL (PostgreSQL): Relational, ACID transactions, schema enforced, good for structured data with relationships (users, orders, todos)
• NoSQL (MongoDB): Flexible schema, document model, horizontal scaling, good for unstructured or varying data

The architect agent recommends PostgreSQL by default. MongoDB is recommended when the spec mentions "flexible schema", "documents", "high write volume", or "no fixed structure".
